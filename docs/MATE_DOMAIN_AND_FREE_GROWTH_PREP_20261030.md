## 1. 独自ドメイン決定時の移行手順

2026-10-31方針：**`kosodatemate.jp` をXServerドメインで取得（未実施）**し、Cloudflareの無料DNSで`care.`、`spark.`、`play.` のサブドメインを管理する。取得可否と所有権は未検証。詳しい安全手順は [`docs/MATE_KOSODATEMATE_JP_REGISTRATION_CUTOVER_20261031.md`](MATE_KOSODATEMATE_JP_REGISTRATION_CUTOVER_20261031.md) を参照。

| サービス | 現在の提供元 | 仮の新ホスト | 主な確認点 |
| --- | --- | --- | --- |
| CARE | GitHub Pages | `care.<取得済みドメイン>` | Pagesのカスタムドメイン、CNAME、HTTPS、`/mate/` 配下からのパス変更 |
| SPARK | Firebase `mate-spark` | `spark.<取得済みドメイン>` | SPARK用Firebaseプロジェクトへ正しく接続、HTTPS/証明書 |
| PLAY | Firebase `mate-play-production` | `play.<取得済みドメイン>` | 独立したPLAY本番プロジェクト、オーナー承認付き再リリース |

### 準備済みの読み取り専用チェック

```bash
python3 scripts/mate_domain_cutover_inventory.py
# 将来、ドメインの所有権を取得した後のみ、候補URLを表示
python3 scripts/mate_domain_cutover_inventory.py --domain example.jp
python3 -m unittest discover -s tests -p 'test_mate_domain_cutover.py' -v
```

出力は**元URLを参照しているファイル一覧**と、変更前の必須チェック。ファイル書き込み、DNS、API、公開、Googleへのリクエストは一切なし。ソースコード全体の自動置換は意図的に禁止（フォームの送信先と旧PLAYの機能差分に影響するため）。

### 一度に実施する本番チェック（ドメイン取得後）

1. DNS、GitHub Pages/Firebaseのホスト割当とTLSを個別に確認する。
2. 3サイトのリンク（ヘッダー・フッター・ガイド・問い合わせ）、フォームの送信先、OG URL、canonical、構造化データ、robots.txt、sitemap.xmlを新URLに一致させる。
3. PLAYは**別のFirebaseプロジェクト**で、最新レビュー済みSHAの本番リリースを行う。旧ChatGPT Sitesの機能との違いを解消し、ドメイン切替前に問い合わせ受信を実証する。
4. `noindex` の混入、旧URLへの正規URL設定、デモ掲載の公開、GA4計測IDの不一致がないか公開サイトで再チェックする。
5. 旧URLから新URLへのHTTP 301/308転送が可能か**提供元ごとに実測**する。GitHub Pagesの `github.io` やFirebaseの `web.app` はCloudflare管理ドメインではないのでCloudflareだけで旧ホスト転送を保証できない。できない場合でも新サイトのcanonical/内部リンクを整え、旧サイトの維持・告知方法を検討する。
6. 切替成功後に、新しいSearch Consoleドメインプロパティ、3サイトの新サイトマップを登録する。旧プロパティは移行監視用に保持。URL検査・リクエストを乱発しない。
7. SNSプロフィール、提携先への案内文、無料媒体の掲載URLを**新URLのみ**で統一する。

参考：Google Search Central「サイトの移転」「リダイレクト」、Firebase Hosting「カスタムドメインを接続する」。

## 2. 掲載前に編集できる検索記事の原稿案

以下は**原稿下書き**。実在する事業者や施設の比較レビューではない。記事に載せる画像、体験談、事業者の具体例は著作権・許諾・実地確認を経て公開する。下書きはインデックスされない場所に保管。

### CARE：「ベビーシッターに初めて連絡するときの依頼メモ」

**記事説明文案**：初回のベビーシッター相談で何を伝えるか迷ったときに使える、日時・場所・お子さまの様子・緊急連絡先の確認メモ。

ベビーシッターを探すときは、いきなり料金だけで比較するより、お願いしたい時間と内容を先に整理すると相談がスムーズになります。

まず、利用したい日と時間帯、場所、希望するサポート内容を書き出しましょう。食事・遊び・送迎など、お願いできる業務の範囲は事業者によって異なります。

次に、お子さまの年齢、普段の生活リズム、伝えておきたい注意事項をまとめます。アレルギーや体調などの情報は、必要な範囲で適切な方法で伝えます。個人情報を公開ページや口コミ欄へ書かないことも大切です。

最後に、依頼を確定する前に、見積もりの内訳、交通費、キャンセル条件、保険の範囲、当日の連絡方法、緊急時の対応を確認しましょう。「どこまでお願いできるか」「当日困ったとき誰に連絡するか」がわかるだけでも、初回の不安を減らせます。

**そのまま使える事前メモ**：希望日時／場所／お子さまの年齢／希望するサポート／事前に伝えたい注意事項／確認したい費用／緊急連絡方法。

**関連導線（ドメイン決定後に設定）**：既存の「初めてのベビーシッターの選び方」ガイド、CAREの事業者検索・問い合わせ。ただし確認されていない事業者を推奨しない。

### SPARK：「習い事の体験レッスンで比べたい6つのこと」

**記事説明文案**：子どもの習い事を体験した後、印象だけで決めないための簡単な比較メモ。楽しさ、通いやすさ、費用、振替、保護者対応、安全面を整理します。

習い事の体験では、子どもの「楽しかった」という反応だけでなく、長く続けられるかどうかも見ておくと判断しやすくなります。

まずは本人がどんな活動に関心を示したかを観察します。次に、片道の移動時間、開始・終了時刻、送迎できる人を確認します。月謝だけでなく入会金、教材費、イベント費など、継続にかかる費用を分けて記録すると比較しやすくなります。

休んだ日の振替や欠席連絡、保護者への説明、安全面のルールも体験時に質問しておきましょう。まだ迷っている段階なら、無理にその場で決める必要はありません。

**比較メモ**：楽しかったこと／移動・曜日／費用の内訳／欠席・振替／先生との相性／安全面と連絡手段。

**関連導線（後日）**：既存の「子どもの習い事の選び方」ガイドとSPARKトップ。ただし実在教室が未掲載の場合は「掲載準備中」を維持し、体験申込可能と誤認させない。

### PLAY：「小さな子どもとのお出かけ先を決める前の確認メモ」

**記事説明文案**：乳幼児連れでのお出かけ先選びで、営業時間、年齢、ベビーカー、授乳・おむつ替え、移動、休憩場所を確認するための下調べガイド。

家族でのお出かけは、行きたい場所を探すのと同じくらい、当日の過ごしやすさも大切です。特に小さな子どもと一緒なら、無理のない移動と途中で休める余裕を考えたいところ。

候補を見つけたら、公式サイトで最新の営業日・営業時間・予約要否・対象年齢を確認します。ベビーカーの利用可否、授乳室やおむつ替え設備、屋内で休める場所も施設ごとに異なります。

移動では、エレベーターや段差の有無、雨の日のアクセス、帰り道も見ておくと安心です。予定を詰めすぎず、当日の体調や天候に応じて変更できる候補を用意するのも一案です。

**確認メモ**：営業時間／対象年齢／予約／ベビーカー／授乳・おむつ替え／移動時間／休憩場所／雨天時の代替案。

**関連導線（後日）**：既存の「雨の日の子連れお出かけチェックリスト」ガイドとPLAYトップ。施設の設備・営業情報は公式の最新情報に従う。
