# MATE 営業・掲載成長の自動運用設計（2026-11-10）

## 目的と範囲
- CARE / SPARK / PLAYは同じ家庭を対象にするが、**営業相手の業種・訴求・掲載申請URLは別**。
- 営業候補数、実送信件数、掲載申請、事務局の承認、実公開、掲載完了メールを混同しない。
- 未承認掲載、宛先の営業拒否、配信停止の無視、個人の保護者データを使った送客、勝手な有料化を禁止。

| サービス | 優先対象 | MATEの価値 | 自己申請 |
|---|---|---|---|
| CARE | ベビーシッター・訪問保育・病児保育・送迎など | 子育て家庭にサービスを紹介 | https://care.kosodatemate.jp/contact.html |
| SPARK | ピアノ・音楽・語学・プログラミング・ロボット・運動・アートの教室 | こどもの習い事を探す家族に教室を紹介 | https://spark.kosodatemate.jp/partners.html |
| PLAY | 親子向け陶芸・ワークショップ・農園/収穫・料理/食育・自然・体験施設 | 親子のお出かけ・体験を探す家族に紹介 | https://care.kosodatemate.jp/play-listing.html |

## 今回実装した仕組み
### 業種別候補の継続追加
- 元の `3サービス営業リスト` を重複防止して取り込み。
- `SPARK営業候補` の教室と `営業管理DB` のCARE事業者に公式HTTPSが確認できる場合、`営業候補_自動収集` に未登録の相手を追加する（毎回上限100）。
- これらの追加候補は必ず `UNVERIFIED / 窓口確認待ち` とし、公式サイトの存在だけで送信しない。
- `収集元設定V1` の公式CSV経由取り込みも既存の仕組みを維持。利用・再配布許諾がないCSVを自動で追加しない。
- 全候補を各サービスに固定割当し、適合性の高い業種名を先に確認する。業種名による機械判定は**営業同意の証拠ではない**。

### 毎日の実送信を可能にする安全なゲート
- `scripts/mate_auto_ops_v4.gs` が `mateAutoOpsV4Cycle` の毎時トリガーで候補収集、公式窓口監査、配信停止、返信、ログ、送客台帳を更新。
- 実際の外部メールは、本人が設定する `MATE_AUTO_SEND=ON` と `MATE_OUTREACH_PHASE=PILOT/LIVE`、送信者の正しい名称・住所、法令レビュー、送信先の確認済み状態をすべて満たした時だけ。
- PILOTで**1通/日**、LIVEでも**最大5通/日**。各サービスで同じ宛先があれば適合度の高い案内だけを1度送る。
- V4ログだけでなく過去365日の **MATE Gmail「送信済み」** も照合し、手動送信した相手に再送しない。Gmail検索が失敗・上限に達した場合は外部メール送信を停止。
- 配信停止・営業拒否は次回以降の送信を停止。返信を機械的に承認扱いしない。予約・利用者フォームに営業送信しない。

### 掲載申請から公開まで
- 申請受付と運営者通知は現行直接受付GASで対応。事務局が申請者権限、写真の掲載権限、無料条件、事業者情報を確認する。
- CARE/SPARKはGitHub承認済みデータ同期。PLAYは別リポジトリの承認済みデータ同期。
- `mate_publication_completion_mail.gs` の `matePublicationCycle` が本番JSON内の掲載ID/事業者名を確認してから、公開台帳を `公開確認済み` にし、ONなら掲載完了メールを1度だけ送る。
- 画像未登録や画像取得失敗のときはカテゴリーに合った上品なイラストを表示。本人の顔や作品がトリミングされないよう実画像は contain 表示。
- 登録済みの実写真5枚については、`掲載画像V1_非公開` の許諾と審査状態に加えて**画像転送の成功**が必要。今回、転送失敗をHTTPステータス/画像形式/容量別の集計ログで確認できるよう変更した。

### 日次KPI
- `installMateV4DailyDigest` で9時台に運営者アカウントへ日次サマリー。候補数（3サービス別）、承認済み申請、本日の送信試行、未審査申請件数を個人情報なしで集計。
- ChatGPTの「MATE日次営業・承認チェック」も設定（閲覧・通知のみ、外部メール送信や承認はしない）。
- 追うべきファネル：**適格候補 → 実送信 → 返信 → 掲載申請 → 人間承認 → 実公開 → 完了通知**。
- 本番の公開URL、メール送信記録、画像公開状況を最終照合して初めて「完全稼働」とする。

## 本番導入時の人手が必要な操作
**GitHub更新はGoogle Apps Scriptには自動で反映されない。**

1. `kosodatemate@gmail.com` で営業の既存Apps Scriptプロジェクトを開き、`mate_auto_ops_v4.gs` の既存コードを最新版へ更新（同名ファイルを重複追加しない）。専用プロジェクトがない場合は新規 `MATE_営業自動化V4` を作る。直接受付の `doPost` や掲載承認GASを上書きしない。
2. `previewMateOutreachReadinessV4` を実行。**ON前に**登録候補・送信根拠・配信停止・送信者の正式名称と住所を確認する。
3. `installMateAutoOpsV4` を実行して1時間ごとに公式窓口確認/候補追加/返信処理を行う。ここまでは営業送信OFFでも可。
4. `installMateV4DailyDigest` を実行して毎日9時台の本人向けサマリーを有効化。
5. 法令確認と宛先確認後、明示的に `MATE_SENDER_NAME` / `MATE_SENDER_ADDRESS` / `MATE_AUTO_SEND_LEGAL_REVIEWED=YES`、適切な公開事業用アドレス例外のレビュー後のみ `MATE_PUBLIC_EMAIL_EXCEPTION_REVIEWED=YES`、`MATE_OUTREACH_PHASE=PILOT`、`MATE_DAILY_CAP=1`、最後に `MATE_AUTO_SEND=ON` を設定。まず本当に1件だけの小規模送信と受信停止方法を確かめ、その後で段階的にLIVEへ。
6. 記録・配信停止を検証できない場合は `MATE_AUTO_SEND=OFF` に戻す。スイッチを外しても候補収集と承認待ち通知は別。
7. `MATE 直接掲載受付` プロジェクトの `checkMateMediaSetupV1` が READY でも画像公開の成功とは別。再同期の画像ログで `metadata_http_403/404` なら、実際の公開専用サービスアカウント（CIのJSONに含まれる `client_email`）が画像保存フォルダの閲覧者か照合する。**サービスアカウントの秘密鍵は貼らない**。
8. PLAYのUI変更は `mate-platform-private` で別途手動承認SHAによる本番リリースが必要。自動データ同期だけでUI変更は反映しない。

## 未確認事項

- 営業ログV4の既存行だけでは過去のGmail手動送信を網羅できない。
- 実写真5枚のDrive取得失敗理由は、本番の再同期ログが出るまで断定できない。
- SPARKは1件実掲載/掲載完了メール送信済み。CARE/PLAYは同等の実在申請について全工程E2E未検証。
