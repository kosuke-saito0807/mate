# MATE 営業拡大：候補純増・公式連絡先確認・掲載申請（2026-11-15）

## 目的と優先順位
1. CARE・SPARK・PLAYそれぞれの**新規事業者候補の純増**
2. **公式事業者サイトで確認した部署共通メール**の増加
3. Gmail送信履歴・配信停止・営業拒否・送信根拠を確認した**初回メール**
4. 返信・外部事業者による実際の掲載申請・掲載承認の観測

配信枠を無理に増やさない。公式サイトにメールがあるだけでは掲載の同意にならない。メール配信条件は日本の広告メール規制等を事前に満たす必要がある。

## 自動処理
- 営業GAS: `scripts/mate_auto_ops_v4.gs` / `mateAutoOpsV4Cycle`（既存の時間トリガー）
- 公式公開データ: BODIK CKAN `package_search`、CARE・SPARK・PLAYで各1クエリ/日、キーワードを日替わりに切り替え。自治体発行・CC BY/CC0・CSV・公開BODIKリソースのみを自動収集元として登録
- 収集元上限: カタログから新規最大6件/日、全体最大80件。外部API障害時は1日1回に制限
- CSV取得: 1実行最大8収集元。未取込・最終取得が古いものを先に、サービス間で順繰りに取得。CSV失敗は当日再試行しない
- 取り込み: HTTPS公式URL、施設/事業者名、サービスとの一致を確認。公式URLに `http://` や `www.` がある場合はHTTPS候補へ正規化するが**接続できる証明とはしない**
- URL安全性: IPリテラル、ローカル/内部/予約ドメイン、ポート指定、外部リダイレクトを拒否
- 連絡先監査: 公式サイト・同一ホストのトップ・問い合わせ/会社概要を確認。ページ本文の「お問い合わせ」表記と業務用部署共通メールを認識。個人アドレスはCSVから取り込まない
- 送信: 従来の送信者本人確認、用途/法的根拠・新鮮な確認日、拒否表示、配信停止、全サービス共通の宛先重複防止、過去Gmail送信履歴、当日/サービス別上限をすべて保持
- 管理: 受信拒否・ハードバウンスを隔離し、送信予約が曖昧な場合は自動再送しない
- 掲載: 申請・審査・公開・課金を自動承認しない。受信した申請と送信履歴の名称一致は因果関係ではなく参考指標

## 見るべき指標
- `diagnoseMateV4Health()`: active/phase/dailyCap、候補総数、サービス別有効CSVソース、公式監査、送信可能数、送信ログ、送信結果不明
- `diagnoseMateV4Backlog()`: 宛先欠落、営業拒否、未確認、根拠期限切れ、既送信の重複分類
- `diagnoseMateOutreachApplicationsV4()`: 内部テストを除外した外部事業者の実申請と、同一事業者の送信後名称一致
- `mateV4DailyGrowthDigest()`: 毎朝、前日の新規候補/公式窓口確認、収集元カバレッジ、送信/返信/停止、実申請数を運営用アカウントへ集計メール

## 編集・運用上の注意
GitHub更新とは別に、時間トリガーの停止・Google OAuth失効・Gmail API制限・事業者側のサイト変更が起こり得る。実数値が増えない場合は「収集元0件 / URL欠落 / 窓口不明 / 拒否/配信停止 / 送信履歴あり」を区別する。個別データの利用ライセンス・禁止事項を尊重し、メール先の非公開個人情報や子どもの情報は収集しない。
