# MATE：172件の営業自動化と掲載依頼後の手順（2026-11-01）

## 営業候補の現状
- 172件が営業候補タブに存在。2026-11-01時点で業務用メール欄に値があるのは89件、残り83件は空。
- メール候補は**受信許可を意味しない**。公開企業サイトでの検証と拒否表示の有無で適格性を判定。未確認・取得失敗・個人メール・拒否表示のある宛先は自動送信しない。
- メールなしの企業には、公式サイトの単一の公開業務用メールを発見できた場合にだけ候補へ補完。確認不能な企業はメール自動送信不可。フォーム送信を自動化して抜け道にしない。

## 初回だけ行う設定（専用アカウント kosodatemate@gmail.com）
1. [営業管理DB](https://docs.google.com/spreadsheets/d/1CLJeXuznctRtH8Y3AMZ2XyOu3dQedmh9obBDrPlIEuQ/edit) →拡張機能→Apps Script。
2. V4専用の .gs ファイルだけを [最新版](https://github.com/kosuke-saito0807/mate/blob/main/scripts/mate_auto_ops_v4.gs) の Raw コードで全文置換し保存。他のフォーム用関数は触らず、古いV4との重複を防ぐ。
3. 既存トリガー `mateAutoOpsV4Cycle`（1時間ごと）が存在することを確認。未設置なら `installMateAutoOpsV4` を1回だけ実行。
4. `mateAutoOpsV4Cycle` を1回実行。ログの `publicAudit` は最大4件の公式ページ確認結果。送信がOFFでも確認処理は動く。URLアクセス権限を求められたら許可する。
5. 実際にメール送信を有効にする前に、特定電子メール法の公開事業用アドレス例外の適用可否、拒否表示、メール文面と責任者の正式名称・住所・配信停止方法、利用規約・Gmail送信ポリシー、業務上の送信権限を確認する。
6. 条件を満たした場合にのみ Apps Script プロジェクト設定→スクリプト プロパティに以下を設定：
   - `MATE_SENDER_NAME=MATE運営事務局`（送信者の表示名。契約・法定上の実際の事業責任者と混同しない）
   - `MATE_SENDER_ADDRESS` = 実際の事業所在地（GitHubに公開しない）
   - `MATE_AUTO_SEND_LEGAL_REVIEWED=YES`（責任者が確認したことを意味する）
   - `MATE_PUBLIC_EMAIL_EXCEPTION_REVIEWED=YES`（公式サイトで自ら公表した業務用アドレスの例外を確認したことを意味する）
   - `MATE_AUTO_SEND=ON`（営業メール自動送信スイッチ）
   - `MATE_DAILY_CAP=5`（最大5通／日。送信先が揃っても急いで一斉配信しない）
7. 変更後に最初の候補・実際の件名・送信ログを確認し、想定外なら `MATE_AUTO_SEND=OFF` に戻す。

公式公開メールの自動検証だけ停止したい時は `MATE_PUBLIC_SITE_AUDIT=OFF`（未設定なら監査ON）。調査しても法的な適格性を機械で完全には保証できない。判断が必要な宛先は担当者確認へ。

## 毎時実行の動き
1. 既存CRM・許可済みCSVから候補を取り込む。
2. 公開公式HTTPSページを最大4候補チェック（最大2URL/候補、HTTP 200、250KB以下、非リダイレクト）。同じ公式ホストに限定する。
3. 事業者のサイトに明示された一般業務窓口メールを確認し、拒否表示がある場合は送信保留。既存メールと照合し、メールがなければ一意の業務用メールを発見したときだけ補完。根拠URL・検証日・結果を営業候補に保存。
4. 上記の明示スイッチがONで、適法な根拠が揃ったメールだけ `営業可能候補` に切り替える。
5. 1日最大5通、同じ候補キーや宛先への二重送信防止、配信停止を尊重。送信結果の曖昧な失敗は自動再送しない。
6. 日次最大3件の運営者宛社内ドラフト、返信・停止監視、取次台帳更新を継続する。

**注意：** 公開メール例外はすべての業務用メールに機械的に適用できるわけではない。公式サイトを取得できない・掲載禁止表示がある・複数メールがあって特定できない場合は送らない。172件全部への送信を保証するものではない。

## 掲載依頼後の実運用

### A. 掲載申請の受付
- CARE: https://care.kosodatemate.jp/contact.html
- SPARK: https://spark.kosodatemate.jp/partners.html
- PLAY: https://care.kosodatemate.jp/play-listing.html
- 3サイトの本番掲載申請は独立した直接受付GAS Webアプリから `掲載セルフ申請` と `掲載申請連絡先` に保存され、申請者へ自動受付メールを返す。受付メールを取り込む旧 `syncMateSelfServiceApplications` は使わない。エラー・不審申請は手動確認し、無断承認しない。
- `掲載セルフ申請` のX列には直接受付証跡 `WEB-...` が保存される。2026-11-01のCARE/SPARK/PLAY本番テストも「差戻し」にして非公開。申請者の連絡先は事務局用タブにのみ保存する。

### B. 人が必ず確認する項目
- 公式サイト・会社／教室名・所在地・カテゴリ・紹介文・料金や年齢などの事実、画像の利用許諾、同意の証拠。
- 申請した人が、その事業者を代表して掲載を許可できるか。本人に掲載希望の意思があるか。
- `掲載セルフ申請` タブの `Y:審査状態=承認`、`Z:担当者権限の確認=確認済み`、`AA:審査者` を実際の審査完了時のみ入力。 `U:情報確認日` と `V:掲載申請の意思`、`X:GmailメッセージID` も整合。
- 公開IDはサービスに応じて自動または運営設定。未審査の申請は公開しない。

### C. 承認後のサイト反映
- `publishReviewedMateApplications` は、人が審査・権限確認を完了したCARE申請を `営業管理DB` に準備し、`掲載契約` に **未契約** の無料ドラフトを作成する（新GASコード反映後）。CAREの公開データ同期はさらに契約ID・契約先ID・同意者・同意日時・証拠・条件版・開始日/終了日が揃う有効な契約と照合し、契約なし/未契約/期限切れなら **公開対象0件** とする。ステータスは `契約確認待ち`。旧版GASから登録されたCAREも、GitHubの公開同期が契約を確認するため無契約のまま公開されない。
- SPARK申請は `SPARK営業候補` へ反映すると同時に `掲載契約` に **未契約** の下書きを作る。独立に契約者、同意日時、合意証跡と条件を確認して `状態=有効` にするまでサイト公開対象にならない。
- PLAYは `掲載セルフ申請` と `掲載契約` を突合。公開IDと掲載先ID一致、審査者・権限確認・掲載意思、情報確認日、有効契約、契約期間・同意証跡・カテゴリ等の全条件が必要。承認済みデータ専用自動同期はGitHubの設定フラグと「既存本番UIがレビュー済み」の条件が揃った場合のみ有効。
- CARE/SPARKの同期： https://github.com/kosuke-saito0807/mate/actions/workflows/sync-smartsheet-public.yml
- CAREの契約ドラフト自動作成を有効にするには、既存の **MATE営業管理DBに紐づく運用Apps Script** の `mate_self_service.gs` だけを[最新版](https://github.com/kosuke-saito0807/mate/blob/main/scripts/mate_self_service.gs)に更新・保存する。`doPost` や直接受付用の別GAS、V4営業自動化を変更しない。既存の毎時トリガーはそのまま使用する。
- PLAYの同期： https://github.com/kosuke-saito0807/mate-platform-private/actions/workflows/play-approved-live-data-sync.yml
- サイトの本番検索／詳細リンクまでを実際に確認し、掲載依頼者へ掲載URLを通知する。今のコードでは**全サービスの事業者への掲載完了通知の全自動送信は未実装**。

### D. 送客・有料化
- GA4の `mate_partner_click` をクリックログとして記録（実際の送客成立とは別）。
- 家族の問い合わせは運営Gmailに保持、Sheetsの `問い合わせ管理` で受付番号・紹介先ID・同意状況・Gmail証跡・結果を管理。
- 保護者の情報提供同意と事業者の取次許諾、実際の紹介実行とその証跡が揃った時点で `送客実績V1` に取次記録。無断で家族の連絡先を第三者へ渡さない。
- 初期は無料掲載。実績が確認された先に個別に有料提案し、成果定義・単価・返金・二重課金禁止・開始日を含む合意が成立してから課金。自動有料移行はしない。
