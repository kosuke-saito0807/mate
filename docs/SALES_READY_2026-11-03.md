# MATE｜営業開始前のサイト改善・確認リスト

最終更新：2026-11-03

このリストは **Webサイトの改善** と **掲載・営業運用の開始条件** を分けています。掲載や契約を自動承認せず、既存の個人情報・同意フローを保持します。

| 分野 | サイト上の対応 | 検証 |
|---|---|---|
| 初めての訪問者の不安解消 | CARE / SPARK / PLAYに、予約・料金・掲載許諾・申請を説明するFAQ各4問 | 公開HTMLとテストビルド |
| 営業の送客導線 | 既存の事業者向けCTAに加え、FAQ下に明確な掲載相談リンク | フォームの宛先を検査（送信はしない） |
| サービス間回遊 | 3つの相棒へのナビゲーションを全サイトに追加。現在位置を明示 | リンク先URL・モバイル表示 |
| 信頼性 | 予約確定・保育品質・体験枠の保証と誤認させず、許諾確認後の掲載であることを明示 | コンテンツ検査 |
| アクセシビリティ | キーボード操作できるネイティブFAQ、フォーカス輪郭、44px以上のタップ対象、画面幅による1列切替 | PC・スマホのブラウザQA |
| 集客基盤 | 既存のcanonical・サイトマップ・GA4・公式ガイドへのリンクを維持 | 既存のSEO／GA4テスト |
| 営業反響の計測 | 掲載相談リンクのクリックを個人情報なしで匿名イベントとしてGA4へ送信 | イベントの静的検査 |
| 公開ルール | CARE：GitHub Pages／SPARK：Firebaseの自動公開。PLAY：専用テスト環境への自動反映と本番手動承認 | CI／本番リリース証跡 |

## コード変更だけでは完了と判定できないこと

1. 実在の掲載事業者・教室・体験の担当者の権限、許諾、情報確認日を記録し、必要な審査が終わってから公開する。
2. 受信用メールの到達・担当者への通知・フォームの同意・Turnstileを、運営者が管理する実アカウントで確認する。テストに実在の家族や事業者の個人情報を使わない。
3. Google Search Consoleのインデックス・検索表示・各サイトGA4のリアルタイムデータを管理画面で確認する。
4. PLAYの本番UI反映は、権限のあるリポジトリ所有者が明示的に承認してから独立したFirebase本番へデプロイする。テストサイトへの自動デプロイは本番公開の代替ではない。
5. 営業メールの一括自動送信、有料契約化、フォーム送信による自動承認、第三者への無承諾の取次ぎは、このリリースの対象外。
